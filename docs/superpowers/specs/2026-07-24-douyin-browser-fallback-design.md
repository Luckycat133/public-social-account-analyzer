# 抖音零 Python 依赖浏览器降级设计

## 1. 背景与结论

当前抖音适配器使用 Python 标准库 `urllib` 请求公开账号主页，并尝试解析页面内嵌的
`RENDER_DATA`、`_SSR_DATA`、`__INIT_DATA`、`_ROUTER_DATA` 或
`__INITIAL_STATE__`。抖音主页目前通常返回由 JavaScript 动态执行的页面外壳，导致账号
资料可以通过 `iesdouyin` 公开接口降级取得，但作品列表以 `PARSER_FAILED` 结束。

本设计决定保留现有 HTTP 快速路径，并在作品列表静态解析失败时，自动启动系统已有的
Chrome、Chromium、Edge 或 Brave 浏览器。采集器通过 Chrome DevTools Protocol（CDP）
正常加载公开主页、监听页面自身发出的公开网络响应，并在必要时从渲染后的公开 DOM 中
提取可见内容。

实现保持项目 `dependencies = []`：不新增 pip 或 npm 依赖。浏览器是可选运行环境依赖，
由现有浏览器探测逻辑发现。任务始终使用临时无痕用户目录，不连接用户日常浏览器配置，
不继承登录态，不处理或绕过登录墙、验证码、滑块和访问频控。

## 2. 目标

1. 在无需登录且页面公开可访问时，采集抖音账号资料和最近最多 100 条公开作品。
2. 保持 Python 运行时零第三方依赖，复用标准库实现的 CDP 和 WebSocket 客户端。
3. 优先提取页面正常请求得到的结构化 JSON，DOM 解析只作为二级降级。
4. 继续输出统一 `Profile`、`Post`、`task_status` 和 `stop_reason`，不破坏下游分析流程。
5. 遇平台保护措施时安全停止并保留已经采集的公开数据。
6. 用两个不同类型的真实公开账号验证最近 30 条采集和完整报告链路。

## 3. 非目标

- 不复刻或伪造抖音接口签名。
- 不调用需要账号登录或私有凭据的接口。
- 不读取、复制或保存用户日常 Chrome 配置及 Cookie。
- 不自动处理验证码、滑块、登录提示或频控。
- 不保存完整网络响应、请求头、签名参数或媒体文件。
- 不保证平台未公开展示的播放量、收藏量或其他指标一定可得。
- 不把 DOM 选择器设计为跨任意网站的通用爬虫框架。

## 4. 方案比较

### 4.1 采用：CDP 网络响应监听

让无痕浏览器正常加载公开主页，监听 `Network.responseReceived`，读取满足白名单和数据结构
校验的 JSON 响应正文。该方案不自行构造签名请求，能够直接复用页面已经成功发出的请求，
数据结构也比 DOM 更完整。

### 4.2 二级降级：渲染后 DOM 解析

当页面展示了作品卡片但没有捕获到可用 JSON 时，从公开 DOM 中读取链接、文案和可见指标。
DOM 结构易变且字段覆盖有限，因此只作为二级降级，所有缺失字段保持 `null`。

### 4.3 不采用：接口签名复刻

直接调用抖音接口并生成签名虽然可以不启动浏览器，但实现和维护成本高、页面变更后容易失效，
也可能超出项目“不绕过平台保护”的边界，因此明确不实现。

## 5. 总体架构

### 5.1 `browser_backend.py`：平台无关 CDP 能力

现有 `BrowserSession` 保留浏览器探测、临时用户目录、标准库 WebSocket 和进程清理职责，新增：

- `navigate(url, timeout)`：使用 `Page.navigate` 打开页面并等待基础加载完成。
- `evaluate(expression, await_promise=False)`：执行平台传输层提供的页面脚本。
- `poll_event(timeout)`：读取并返回异步 CDP 事件。
- `drain_events(method=None)`：从事件队列取出已经缓存的事件。
- `get_response_body(request_id)`：调用 `Network.getResponseBody` 获取响应正文。
- `scroll_by(viewports=1)`：执行有限度页面滚动。
- `page_text()`：读取当前公开 DOM 的可见文本，用于限制状态检测。

`_send_cdp` 当前会在等待命令结果时丢弃事件。改造后，非当前命令响应的事件必须进入 FIFO
队列；命令响应与异步事件共享一个接收循环，但不能互相吞掉。实现可以使用 Python 标准库
`collections.deque`，不需要后台线程或第三方异步框架。

该文件不得包含抖音域名、接口模式、DOM 选择器或字段映射。

### 5.2 `_douyin_browser_transport.py`：抖音浏览器传输层

新增平台专用传输组件，负责：

- 启动并关闭 `BrowserSession`。
- 导航到已经通过 `supports()` 校验的账号主页。
- 识别登录、验证、频控和账号不可用页面。
- 从网络事件中筛选候选 JSON 响应。
- 校验响应是否包含作品列表或作品详情结构。
- 控制滚动、超时、去重和日期截止条件。
- 在网络数据不足时执行公开 DOM 降级提取。

建议提供单一入口：

```python
collect_account_page(
    url: str,
    *,
    limit: int,
    date_range: tuple[str | None, str | None] | None,
) -> DouyinBrowserResult
```

`DouyinBrowserResult` 至少包含：

- `profile_raw`: 可选账号原始结构。
- `aweme_items`: 去重后的原始作品字典列表。
- `source`: `network`、`dom` 或 `network+dom`。
- `restriction`: 可选任务级 `stop_reason`。
- `diagnostics`: 不含敏感信息的轮次、耗时、候选响应数和停止条件。

可以使用标准库 `dataclasses` 定义结果类型；项目最低 Python 版本为 3.9。

### 5.3 `douyin.py`：路由、字段映射与状态语义

现有适配器保留以下职责：

- URL 支持判断与短链解析。
- `urllib` 静态 SSR 快速路径。
- `iesdouyin` 账号资料降级。
- 原始抖音字段到统一 `Profile`、`Post` 的映射。
- `DouyinError` 与公开 `stop_reason` 语义。

当 `collect_post_list` 静态路径因缺少或无法识别 SSR 数据而触发 `PARSER_FAILED` 时，默认调用
抖音浏览器传输层。浏览器返回的 `aweme_items` 继续复用 `_build_post_raw` 与
`normalize_post`，避免出现两套字段映射。

浏览器传输层不可用或没有得到可验证数据时，适配器才最终抛出 `PARSER_FAILED`。若传输层已经
检测到登录、验证或频控，则对应原因优先于解析失败。

为表达“已经采到部分作品后遇到限制”，`DouyinError` 增加可选的 `partial_posts` 属性。
`collect_post_list` 先把浏览器结果映射为统一 `Post`，再抛出携带这些作品的限制异常。
`collect.py` 捕获异常时必须先读取并保留 `partial_posts`，然后再根据作品数量决定
`PARTIAL` 或 `FAILED`。不使用采集器全局状态保存部分结果，避免不同任务之间串数据。

### 5.4 `collect.py`：命令行与任务编排

- 抖音静态解析失败时默认启用浏览器降级。
- 新增 `--no-browser-fallback`，允许服务器或受限环境完全禁止启动浏览器。
- 保留现有 `--browser-fallback` 参数以兼容旧调用方式。
- 新增平台无关环境变量 `SOCIAL_BROWSER_FALLBACK=0|1`。
- `BILIBILI_BROWSER_FALLBACK` 保持向后兼容，只继续控制 B站路径。
- 命令行显式参数优先于环境变量，`--no-browser-fallback` 优先级最高。

## 6. 数据流

1. `collect.py` 根据 URL 选择 `DouyinCollector`。
2. `check_access` 使用当前公开 HTTP 路径识别明确限制状态。
3. `collect_post_list` 尝试解析静态 SSR 作品列表。
4. 静态解析成功时直接归一化，不启动浏览器。
5. 静态解析为 `PARSER_FAILED` 且浏览器降级未禁用时，创建临时 `BrowserSession`。
6. 浏览器启用 `Page`、`Runtime` 和 `Network` 域后导航到账号主页。
7. 传输层处理候选响应、提取作品、按 `aweme_id` 去重并滚动。
8. 网络响应无法满足请求数量时，传输层检查公开 DOM 并补充可见作品卡片。
9. `douyin.py` 将原始项目映射为统一 `Post`，应用日期过滤和数量限制；若随后检测到限制，
   通过 `DouyinError.partial_posts` 传递部分结果。
10. `collect.py` 在处理异常状态前合并 `partial_posts`，再落盘数据、状态和脱敏诊断。
11. 上下文管理器无论成功或异常都关闭浏览器并删除临时用户目录。

## 7. 网络响应筛选与解析

网络响应必须同时通过以下校验：

1. 响应 URL 的主机属于允许的抖音公开域名集合。
2. 资源类型或响应头表明正文可能为 JSON；若内容类型不可靠，可以尝试 JSON 解码，但失败后
   立即丢弃。
3. URL 路径匹配已知作品列表或详情候选模式，或者正文通过结构校验。
4. 解码后的对象包含可识别的 `aweme_id` 和作品结构；不能只因字段名称相似便接收。

接口 URL 只能作为候选信号，结构校验是最终依据。这样可以允许平台调整接口路径，同时避免
把无关响应误解析为作品。

`Network.getResponseBody` 返回的 base64 正文使用标准库解码。读取失败只跳过该响应，不能导致
整个任务崩溃。日志记录脱敏后的主机和路径，不记录查询字符串。

## 8. 滚动与停止条件

- 用户数量仍限制为 1 至 100 条。
- 浏览器阶段最长运行 90 秒。
- 最多执行 20 轮滚动。
- 每轮滚动后等待页面正常加载，固定等待用于可靠性，不引入规避检测的随机行为。
- 连续 3 轮没有发现新 `aweme_id` 时停止。
- 达到用户请求数量时立即停止。
- 设置日期下限时，只有在非置顶作品已经按时间越过下限且后续一轮没有发现范围内新内容时，
  才能因日期范围停止；置顶内容不能单独触发提前结束。
- 页面明确显示没有公开作品时返回空列表并由上层映射为 `NO_PUBLIC_CONTENT`。

## 9. DOM 二级降级

DOM 降级只读取公开渲染内容：

- 账号主页中的作品链接或作品 ID。
- 页面可见文案或标题。
- 页面明确展示的互动数字。
- 公开可识别的置顶标记。

DOM 提取必须优先依赖稳定语义特征，例如作品 URL 和 `data-*` 属性，再考虑 class 选择器。
从 DOM 无法确认的发布时间、播放量、收藏量等字段写 `null`，不得从排序或其他互动数推断。

DOM 结果的 `source` 标记为 `dom`，字段可见性按实际可见字段记录，使采集质量报告能够区分
结构化网络数据和页面可见降级数据。

## 10. 合规与隐私边界

- 浏览器使用每个任务独立的临时用户目录。
- 不使用 `--user-data-dir` 指向用户真实配置。
- 不连接已运行的用户 Chrome 调试端口。
- 不导入或导出 Cookie，不接受用户凭据。
- 不自动操作登录、验证码、滑块或其他访问保护控件。
- 不通过刷新、代理轮换、签名伪造或高频重试规避限制。
- 不下载完整图片、视频或音频。
- 不把原始响应写入任务目录、日志或测试夹具。
- 测试夹具只保存人工脱敏且满足最小字段覆盖的 JSON/HTML 片段。

## 11. 状态与错误处理

| 场景 | 有已采作品 | `task_status` | `stop_reason` |
|---|---:|---|---|
| 正常达到数量或自然结束 | 是 | `COMPLETED` | `null` |
| 页面要求登录 | 否/是 | `FAILED`/`PARTIAL` | `LOGIN_REQUIRED` |
| 验证码或滑块 | 否/是 | `FAILED`/`PARTIAL` | `VERIFICATION_REQUIRED` |
| 访问频控 | 否/是 | `FAILED`/`PARTIAL` | `ACCESS_RESTRICTED` |
| 账号不存在或不可用 | 否 | `FAILED` | `ACCOUNT_UNAVAILABLE` |
| 明确没有公开作品 | 否 | `FAILED` | `NO_PUBLIC_CONTENT` |
| 无 Chrome 且静态解析失败 | 否 | `FAILED` | `PARSER_FAILED` |
| 浏览器加载成功但没有可验证作品结构 | 否 | `FAILED` | `PARSER_FAILED` |

找不到浏览器时不新增公共 `stop_reason`，以免破坏现有数据模型。错误日志可以增加内部
`diagnostic_code=BROWSER_UNAVAILABLE`。同理，浏览器启动、CDP 连接和读取响应正文的错误应记录
脱敏诊断，但最终映射到现有任务级语义。

限制状态优先级为：验证 > 登录 > 频控 > 账号不可用 > 解析失败。已取得的作品必须保留，
任务状态由编排层根据 `collected_count` 决定为 `PARTIAL` 或 `FAILED`。

## 12. 测试设计

### 12.1 通用 CDP 单元测试

- `_send_cdp` 等待命令结果时，异步事件进入队列且顺序不变。
- `poll_event` 能区分命令响应、网络事件、超时和连接关闭。
- `get_response_body` 正确处理普通文本和 base64 正文。
- 页面导航、JavaScript 执行、滚动和超时错误均有稳定异常语义。
- 上下文退出时终止进程并删除自有临时用户目录。

全部测试使用假 WebSocket 或假 CDP 消息，不启动真实浏览器、不访问网络。

### 12.2 抖音传输层离线测试

- 从脱敏作品列表响应提取视频与图文作品。
- 从详情响应补充字段，但不覆盖已有非空可靠字段。
- 置顶内容正确标记，且不干扰日期停止条件。
- 重复响应和重复作品按 `aweme_id` 去重。
- 未知 URL 但结构有效的响应可以被接收。
- URL 看似匹配但结构无效的响应必须被拒绝。
- DOM 降级只填写可见字段，缺失字段保持 `null`。
- 登录、验证、频控、空账号和结构变化分别映射正确。
- 诊断输出不包含 Cookie、请求头、查询字符串和完整响应正文。

### 12.3 适配器与编排测试

- SSR 成功时不创建浏览器会话。
- SSR 为 `PARSER_FAILED` 时自动调用浏览器传输层。
- `--no-browser-fallback` 禁止任何浏览器启动。
- Chrome 不存在时最终为 `PARSER_FAILED`，并带 `BROWSER_UNAVAILABLE` 内部诊断。
- 浏览器中途受阻时保留已采作品并形成 `PARTIAL`。
- `DouyinError.partial_posts` 能被编排层读取并落盘，异常不会吞掉部分结果。
- 网络与 DOM 两条路径复用相同统一字段映射。
- 抖音专用测试必须显式导入和调用 `DouyinCollector`，不能以通用去重测试代替。

### 12.4 真实公开页面验收

选择一个机构或品牌账号和一个个人创作者账号。每次验收记录：

- 测试日期和公开主页 URL。
- 浏览器版本和操作系统。
- 请求数量、实际采集数量、任务状态和停止原因。
- 账号字段覆盖率及作品指标覆盖率。
- 人工抽查 10 条作品的结果。

验收条件：

1. 每个账号目标采集最近 30 条；页面公开内容不足时记录实际上限。
2. 账号资料和核心作品字段人工抽查准确率至少 95%。
3. 置顶、重复、缺失指标和日期范围处理正确。
4. 完整生成 CSV、JSON、Markdown 和 HTML 报告。
5. 遇登录或验证时确认安全停止，不把目标改为绕过限制。
6. 仓库保存脱敏验收摘要，不提交原始网络响应。

## 13. 文档与发布状态

在两个真实公开账号通过验收之前：

- README 中抖音成熟度应标记为“实验性支持”或黄色状态。
- Roadmap 不应宣称抖音端到端能力已经全部验证。
- 平台文档应明确 Chrome 是可选系统运行环境，项目仍保持零 Python 第三方依赖。

两个账号通过验收后，才可以将抖音恢复为“绿色 P0”，并在变更日志记录测试日期、样本范围、
字段覆盖边界和已知限制。

## 14. 完成标准

本功能完成需同时满足：

- 所有新增离线测试通过，且原有测试无回归。
- 抖音专用测试覆盖静态、网络监听、DOM 降级和限制状态。
- 两个真实公开账号完成端到端验收。
- 未新增 pip/npm 运行时依赖。
- 未读取登录态、保存敏感网络数据或实现保护绕过逻辑。
- README、平台说明、使用说明和变更日志与真实成熟度一致。
