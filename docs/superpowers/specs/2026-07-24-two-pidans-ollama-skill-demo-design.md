# “两颗皮蛋”本地小模型 Skill 演示与技术汇报设计

**日期：** 2026-07-24  
**受众：** 技术团队  
**状态：** 已获用户确认，待实施  
**演示时长：** 3–5 分钟  
**需求基线：** 《公开社交媒体账号内容分析 Skill 产品需求文档 V1.0》的 P0 范围

## 目标

使用 Claude Code 搭配本地 Ollama 小模型，演示小模型作为执行 Agent 读取并调用本仓库的公开社交媒体账号分析 Skill，对哔哩哔哩 UP 主“两颗皮蛋”完成一次可复现、可审计的 P0 端到端任务，并将调研数据、分析报告、演示视频和技术汇报 PPT 整理为一套交付物。

演示重点不是让小模型自行编造或计算数据，而是展示小模型如何理解 Skill 契约、调用确定性工具、检查中间产物、完成语义分类并汇总结果。采集、归一化、统计和渲染由仓库脚本执行，模型负责流程编排、异常判断、内容分类和策略归纳。

## 范围

### 包含

- 调研并确认“两颗皮蛋”的哔哩哔哩公开账号主页 URL 与 UID。
- 采集最近 30 条公开内容；若公开访问限制导致不足 30 条，如实保留已采集样本并说明停止原因。
- 完成 PRD P0 的任务创建、平台识别、公开访问检查、账号资料采集、内容列表与详情采集、数据归一化、数据质量报告、内容自动分类、指标计算、高低表现拆解、证据追溯和多格式报告生成。
- 录制真实执行过程，压缩等待片段，制作 3–5 分钟 MP4 演示视频。
- 制作面向技术团队的 8–10 页 PPT，说明架构、模型与脚本分工、数据链路、关键结果、失败降级、合规边界和可复现方法。
- 保留原始数据、标准化数据、分析结果、报告、录制源文件、最终视频、截图、命令记录和来源说明。

### 不包含

- PRD P1 评论采样、缓存与增量采集演示。
- 抖音、微博、小红书或视频号调研。
- 登录、验证码处理、平台限制绕过或账号接管。
- 私有后台指标、完整媒体下载或未经公开页面支持的推测字段。
- 跨账号因果比较或对 UP 主个人属性进行无证据推断。

## P0 数据契约

### 任务与账号数据

- 任务：`task_id`、`platform`、`requested_limit`、`date_range`、`analysis_goal`、开始与结束时间、任务状态、停止原因。
- 账号：UID、名称、主页 URL、简介、认证、粉丝数、作品数、采集时间。

### 内容与公开指标

- 内容基础：BV 号、内容 URL、标题、简介/文案、发布时间、内容类型、时长、分区、标签。
- 特殊标识：合集、动态视频、置顶、原创/转载。
- 公开表现：播放、点赞、投币、收藏、评论、弹幕、分享，以页面或公开接口实际可见字段为准。
- 证据：`source_url`、`collected_at`、`field_visibility`、`collection_status`。

不可见字段必须写为 `null`，不得以 `0` 代替未知值，不得由模型猜测。`post_id + platform` 唯一，置顶内容不得被误判为近期发布。

### 分析数据

- 每条内容分类：主题、形式、内容目的/漏斗阶段、钩子、栏目、原创/转载、产品露出、分析标签和分类置信度。
- 发布节奏：周均发布量、发布时间分布、工作日/周末差异及样本内断更特征。
- 公开表现：指标中位数、P25、P75、相对中位数表现、主题/形式/发布时间组合差异。
- 高低表现：依据分析目标选择前 20% 和后 20%，至少各引用 3 条内容；若有效样本不足，按实际样本说明限制。
- 策略归纳：只描述公开样本中的相关特征，并为核心洞察附具体帖子 URL 和公开指标。

## 技术架构与职责边界

```text
技术人员输入目标账号与分析目标
             │
             ▼
Claude Code / 本地 Ollama 小模型执行 Agent
  ├─ 读取 SKILL.md 与平台/数据/分析规则
  ├─ 规划并调用脚本
  ├─ 检查状态、缺失值与数据质量
  ├─ 完成内容语义分类
  └─ 汇总证据与结论
             │
             ▼
确定性 Skill 流水线
  collect.py → normalize.py → analyze.py → render_report.py
             │
             ▼
source JSON/JSONL + CSV + analysis.json + Markdown + HTML
             │
             ▼
抽查验证 → 录屏剪辑 → 技术汇报 PPT
```

小模型不得修改采集得到的公开指标，也不得直接替代统计脚本。模型分类结果与原始数据、确定性数字分层保存，以便重新分类和审计。

## 演示脚本

1. 展示本地环境、所选 Ollama 小模型和 Skill 目录。
2. 向执行 Agent 提交“两颗皮蛋”账号主页、最近 30 条、重点分析内容结构与发布节奏的任务。
3. 展示 Agent 读取 Skill 约束并确认平台、范围、评论关闭和合规边界。
4. 展示采集、归一化和数据质量摘要；长等待片段加速，但保留关键终端输出。
5. 展示模型读取分类提示并写入结构化分类结果，随后由脚本校验与回填。
6. 展示指标计算、高低表现拆解和证据链接。
7. 打开最终 Markdown/HTML 报告，并展示 CSV、JSON 等可复核产物。
8. 以技术总结收尾：模型负责决策与语义，脚本负责事实与计算，失败可安全降级。

若 Ollama 当前没有合适的已安装模型，实施时优先选择本机已有、支持足够上下文和结构化输出的最小可用中文模型；如必须下载模型，将先征得用户对网络下载的授权。模型名称、量化版本、上下文配置和推理耗时写入来源说明和 PPT。

## 失败处理与降级

- Ollama 服务未运行：启动本地服务后重新探测，不更改采集目标。
- 小模型无法稳定执行完整 Agent 工具调用：保留同一 Ollama 模型作为决策/分类主体，由受控编排器逐步提供命令接口；PPT 中明确披露实际调用架构。
- 公开页面受登录、验证码或访问限制：立即停止对应访问，不尝试规避；保存已获得数据并记录 `LOGIN_REQUIRED`、`VERIFICATION_REQUIRED` 或 `ACCESS_RESTRICTED`。
- 目标样本不足 30 条：继续完成可执行的归一化与报告，显式说明样本数量、字段覆盖率和无法回答的问题。
- 单条内容失效或解析失败：跳过单条、保留失败 URL 与原因，不让单条失败终止整个任务。
- 语义分类输出不符合枚举或 JSON 结构：拒绝回填，向同一模型提供校验错误并重试；不得静默修正为未披露的人工结论。
- 录制过程中出现长等待或不稳定步骤：保留真实完整源录制，最终视频只做等待加速和无关片段裁切，不伪造终端结果。

## PPT 结构

PPT 计划为 8–10 页，使用适合技术评审的简洁视觉体系：

1. 项目目标与演示结论。
2. PRD P0 范围与验收口径。
3. Claude Code、Ollama 小模型与 Skill 的职责边界。
4. 端到端数据流和关键命令。
5. “两颗皮蛋”公开样本与数据质量。
6. 内容结构、发布节奏和公开表现结果。
7. 高低表现案例与证据链。
8. 真实演示关键画面与视频入口。
9. 异常降级、合规与可复现性。
10. 技术结论、限制和下一步。

视频以可点击链接和封面关键帧进入 PPT；如果 PowerPoint 环境支持可靠的本地视频嵌入，则同时嵌入 MP4，并保留旁路文件以避免跨机器播放失败。

## 验证与验收

- 确认本地 Claude Code 与 Ollama 的版本、模型名称和可复现启动方式。
- 小模型能够读取 Skill 并驱动 P0 任务；任何受控编排器介入均在材料中披露。
- 目标为最近 30 条公开内容；不足时有明确停止原因和数据质量说明。
- 人工抽查账号资料及至少 10 条内容的核心公开字段，目标准确率不低于 95%。
- 检查重复、置顶、失效内容、时间格式、不可见字段 `null` 规则及字段覆盖率。
- CSV、JSON、Markdown 和 HTML 均存在且可正常打开。
- 每项核心洞察至少关联一个具体帖子 URL，核心洞察证据覆盖率为 100%。
- 高低表现分析至少各引用 3 条有效内容，或明确记录样本不足。
- 演示视频时长 3–5 分钟、画面和文字清晰、关键步骤连续且无伪造结果。
- PPT 全页渲染检查，无溢出、遮挡、坏链接或不可读截图；视频文件与 PPT 相对位置稳定。

## 交付完成定义

当真实 P0 任务产物、可复现运行说明、3–5 分钟 MP4、技术汇报 PPT、调研来源说明和验证清单均已生成并通过上述检查时，本任务完成。若 B站公开访问限制阻止 30 条完整采集，交付仍可完成，但必须在视频、PPT 和报告中一致披露实际样本量、停止原因与分析限制。
