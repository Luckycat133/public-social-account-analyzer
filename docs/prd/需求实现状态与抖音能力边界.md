## 结论

项目已经具备 B站、抖音、微博与小红书的统一采集入口、不可变工作区、归一化、确定性指标、可审计报告和安全停止链路。微博与小红书是 P1 实验性公开页管线：前者使用公开 AJAX，后者只读取直接主页嵌入状态；二者可选用户授权 Cookie 会话，但均未完成实机正向验收，也不保证全量。抖音能力仍必须按数据来源区分：

| 模式 | 能力 | 能否声明「全部作品」 |
|---|---|---|
| 任意公开账号、无需登录 | `collect.py --all` 在安全预算内滚动并被动观察公开列表响应；末页后停止滚动并排空到一次静默轮询 | **条件成立**。只有精确 HTTP 200、可选 API 状态为整数 0 的同账号可信列表明确出现 `has_more=false`，作品 ID/官方 URL 一致，且会话内全部目标账号列表候选形成账号/结构/分页事实一致的观测时，才写 `is_exhaustive=true`；HTTP/API 错误、歧义绑定、候选失败或分页冲突均非穷尽：已有作品为 `PARTIAL`，0 个有效作品为 `FAILED` |
| 用户授权 Cookie 会话 | `collect.py` 或完整编排通过 `--douyin-cookie-file` 把用户合法会话注入隔离临时浏览器；不读取本机浏览器 profile，不持久化 Cookie | **条件成立**。可继续匿名页因登录墙不可见的账号列表，但只有同样观察到可信末页时才声明穷尽；Cookie 过期、验证码、频控或绑定冲突仍可能得到 `PARTIAL/FAILED` |
| 已知公开作品 URL | `--enrich-details` 对列表中已有的真实作品 URL 补充缺失详情；不能据此发现新作品 | 不能；它只补已有作品字段 |
| 账号本人授权 | `collect_douyin_authorized.py --all` 先用同次 OAuth 的 access token + open_id 完成 userinfo 精确身份回证，再使用官方 `/video/list/` 分页 | **条件成立**。只有官方响应 `has_more=false` 时才声明该授权账号的全部公开视频已遍历；当前仅完成离线契约测试，尚无真实凭据在线验收 |
| Web 索引证据 | Agent 核验公开精选页或精确主页索引后，由离线导入器生成可审计快照；显式日期窗口只保留发布时间可验证且在范围内的记录；可从同账号密封直连提交合并较新的公开资料 | 不能；固定为可能陈旧、非实时、非穷尽的 `PARTIAL`；日期未知的搜索索引不能用于「最近 N 天」排名 |

因此，即使用户提供授权 Cookie，项目也不能保证任意第三方抖音账号的所有历史视频都可查。代码会尽量采集，并明确区分匿名与授权会话、「达到数量」「预算停止」「平台阻断」和「观察到末页」，不会把部分结果冒充全量。

核心运行时仍为 Python 标准库零额外依赖。浏览器路径可使用系统已有 Chrome/Chromium/Edge/Brave 或已安装的 Playwright Chromium/Headless Shell 缓存，但不新增 Python 包、不安装浏览器，也不接管本机浏览器 profile；用户可在对话中粘贴授权 Cookie，Agent 仅在任务期受限临时文件中交接。测试需要 `pytest`，Web 索引取证需要 Agent 环境提供搜索/打开连接器，OpenAPI 全量路径需要账号本人提供同次 OAuth 返回的有效 access token 与 open_id。

## 功能需求映射

状态含义：`完成` 表示代码与离线自动化合同已闭环；`条件完成` 表示完整实现存在，但在线可用性、外部授权或人工验收尚未满足；`部分完成` 表示只实现了可独立验收的子合同，PRD 仍有本地实现缺口；`未完成` 表示尚无足以通过该项的实现与验收证据。

|---|---|---|---|
| FR-001 任务创建 | 完成 | `collect.py` 支持账号 URL、显式限量 1–100、两平台 `--all` 有界预算、日期范围、分析目标、评论开关和独立输出目录；完整采集器可安全创建一层缺失的生成物父目录；Agent 对模糊范围按用户目标与证据充分性选择分阶段限量或完整入口，参数错误在联网和任务叶目录写入前失败 | 无 |
| FR-002 平台识别 | 完成 | B站、抖音、微博与小红书适配器只接受各自规范账号主页；统一 URL 策略拒绝作品页、搜索页、凭据、非 HTTPS 和相似域名；只有昵称/抖音号时，Agent 可从抖音第一方移动搜索核对身份并取得真实 `/user/<sec_uid>` | 微博与小红书为 P1 公开页实验性管线，不阻塞 B站/抖音 MVP |

## PRD §10 分析交付扩展

FR-013 的「完成」表示标准 JSON/CSV/Markdown/HTML 产物及严格模型输入、证据、安全、渲染合同已闭环；每次真实任务仍须由执行 Agent 完成两阶段 JSON，不能把 prompt draft 当作业务结论。

| §10 交付 | 状态 | 当前实现 | 运行边界 |
|---|---|---|---|
| 账号定位五维 | 完成（工程合同） | 严格固定目标受众、核心内容领域、价值主张、人设/品牌表达、关注理由；每项至少一条冻结父作品证据 | 每个真实任务仍需模型填写并通过证据校验；无有效样本不生成 |
| 内容策略与高低模式 | 条件完成 | taxonomy 矩阵与高低组确定性事实之外，固定输出 6 个高低表现公开文案模式；报告同步渲染证据和限制 | 只能描述公开标题/文案；真实视频开头、画面结构或因果关系不可观察时必须降级 |
| 3–8 个选题方向 | 完成（工程合同） | 数量由证据规模冻结，ID 从 `topic-01` 连续编号，逐项含标题、理由与父作品证据 | 不能无证据凑数；模型失败则 final 为 `PARTIAL` |
| 5 个可复用内容模式 | 完成（工程合同） | 严格要求 `mode-01`～`mode-05`，逐项含名称、配方与父作品证据 | 同上 |
| 4 个可验证实验 | 完成（工程合同） | 严格要求 `experiment-01`～`experiment-04`，含假设、变量、对照、成功指标、判定规则、周期和证据 | 只允许固定公开指标作为成功指标，不声称统计显著性 |

|---|---|---|---|---|
| 名称、简介、抖音号、认证、粉丝、作品数、获赞 | 页面公开时可采；不可见为 `null` | 用户登录后页面明确显示时可采 | 只保留来源明确显示的字段 | 官方 userinfo 回证同一 open_id 后，仅映射响应明确提供的公开字段 |
| 作品 ID 与规范 URL | 页面公开列表/详情可见时可采 | 登录会话列表/详情明确返回时可采 | 精选页可能有；搜索主页索引无真实 ID 时明确使用本地 `idx-*` 且 `post_url=null` | 官方 `video_id`；同 ID 的直接/数字 share URL 可写 `post_url`，非数字 opaque share 仅写 `source_url`，数字异 ID 拒绝 |
| 文案、发布时间、类型、时长、话题 | 列表或已知详情页公开时 best-effort；不猜测 | 同左，且只保留页面明确值 | 仅保留索引明确显示值 | 仅保留官方响应字段 |
| 播放、点赞、评论、收藏、分享 | 仅页面明确公开的指标；未显示为 `null` | 同左，不因登录态推算缺失值 | 仅保留索引明确显示值，不推算总互动 | 仅保留官方响应字段 |
| 评论文本与评论点赞 | `--comments` 开启且无需登录可见时，每篇最多 20 条 | 当前仍受页面接口与验证条件限制 | 不从搜索摘要拼接评论 | 当前授权采集命令不采评论 |
| 曝光、触达、完播、转化、粉丝画像、私信 | 不可采集 | 本项目不采集后台私有数据 | 不可采集 | 本项目不采集 |

## 最终需要登录或账号本人授权的能力

| 能力 | 所需身份 | 当前结论 |
|---|---|---|
| 稳定遍历抖音账号本人的公开视频列表并确认官方末页 | 账号本人完成 OAuth，提供同次返回的 `access_token + open_id` | 工程合同与离线测试完成；仍需一组真实凭据在线验收 |
| 当前匿名页面已显示登录墙的第三方账号最近 30 条 | 用户在对话中提供其合法登录会话的 Cookie | 已实现 `--douyin-cookie-file` 隔离会话；Agent 只在任务期受限临时文件中交接，标记为 `user_authorized_session`，不冒充匿名采集，仍需实机验证 Cookie 有效性和平台可见性 |
| 当前匿名页面已显示登录墙的微博或小红书公开主页 | 用户在对话中提供其合法登录会话的对应域 Cookie | 已实现 `--weibo-cookie-file` 与 `--xiaohongshu-cookie-file`；Agent 只在任务期受限临时文件中交接，记录不写入工作区或报告，仍需实机验证 Cookie 有效性、页面可见性与字段准确率 |
| 登录后才可见的评论列表或评论管理 | 账号本人授权及相应 OpenAPI 权限 | 当前只分析匿名公开评论；授权评论采集未实现，且不影响主内容分析 |
| 曝光、触达、完播、转化、粉丝画像等后台指标 | 账号本人后台登录/授权 | PRD 明确 Out of Scope，本 Skill 不采集；不是待补的匿名能力 |

人工 AC-03/AC-06 可以由真人打开页面填写真值，但登录后可见记录不能反向证明匿名采集能力。自动化流程不接管本机浏览器 profile，只使用用户显式提供的 Cookie 文件，并把访问方式写入覆盖账本。

## 发布检查与剩余工作

1. **已完成**：公开 `--all` 的主页 `sec_uid`、作品作者、空页和末页信号已严格绑定；每个候选先校验精确 HTTP 200、可选顶层 API 整数零状态、作品 ID 别名与可解析官方直接 URL 一致性，再逐项验证 frozen owner、原始条目和游标别名并合并为一个逻辑页。坏项只允许保留其他已验证作品，不能贡献分页事实；一致的多 owner 只提交一次页数/游标/terminal。末页后停止滚动并继续处理到最终无尾随 CDP 调用的静默轮询；任一候选 HTTP/API 错误、未决、绑定有歧义、加载/JSON/结构/作者校验失败或分页事实冲突时，即使已见末页也保持非穷尽，并通过独立复审。
2. **已完成**：已知作品详情页浏览器兜底通过独立复审和无登录真实页复测；当前目标页返回 `LOGIN_REQUIRED`，实现正确停止且未补造详情。
3. **已完成（工程合同）**：taxonomy、business-insight 与可选 comment-insight 模型阶段已实现；账号定位五维、6 个高低公开文案模式、证据驱动的选题/模式/实验及五类评论洞察均有摘要绑定、父作品/评论摘录校验、不可观察降级和双格式报告。
4. **已完成（工程合同）**：采集覆盖账本进入分析前会重新按白名单、精确类型、任务状态、末页信号和作品计数校验；匿名页面与本人授权报告使用各自准确的来源免责声明，不互相冒充。最终完整测试、编译、CLI help、JSON 与 diff 检查的精确结果以交付日志为准。
5. **待外部验收**：补做 AC-01、AC-02、AC-03、AC-10，以及微博/小红书匿名与用户授权 Cookie 的正向实机验收；没有达到即继续保留黄色实验性成熟度。
6. **待账号本人授权**：若要正式宣称授权账号全量可用，需提供同次 OAuth 返回、具备 `video.list` 权限的真实 access token + open_id，完成一次在线身份与末页验收；同时确认 userinfo Content-Type 表/示例差异，以及 `video.list` 当前缺失的 cursor/count 参数表。令牌不得进入 URL、命令行、日志或产物。
7. **待人工与非功能验收**：PRD §10 的工程编排及列表后异常中断恢复已闭环，但 AC-03 仍需外部人工真值，AC-10 仍需真实运营记录及一轮反馈驱动的已合并修改；「正常公开条件下显式 `--limit 30` 全流程不超过 10 分钟」的抖音正向验收仍未完成。2026-07-27 最终匿名复测两账号分别约 15.95 秒与 19.14 秒安全停在登录墙、0 条作品，只证明停止与计时正确，不能替代正向 30 条性能验收。
