## 结论

项目已经具备 B 站、抖音、微博与小红书的统一采集入口、不可变工作区、归一化、确定性指标、可审计报告和安全停止链路。账号名发现由 Agent 统一执行候选搜索和身份核验，再把规范主页交给平台采集器。0.9.0 把这一栈收得更紧：参考文档按需拆分为 `artifact-contract` / `collection-schema` / `analysis-schema` 与 `metrics-and-sampling` / `model-insights` / `comment-insights` 六个模块，Cookie 持久化从临时凭据存储升级为带原子替换、`fsync`、`0600` 权限、符号链接与 UID 校验的私有原语，小红书采集器适配现代 `window.__INITIAL_STATE__` 并以主页路径绑定目标账号，抖音公开路径与 B 站共享 `bounded_attempt_runner` 的会话感知滚动；`task.json` 写入 `skill_release` 与 `skill_contract_sha256`，可定位测试实际运行的 Skill 版本与 SKILL.md 字节。微博 P1 公开 AJAX 适配器默认启用，公开 AJAX `ok=-100` 记为 `LOGIN_REQUIRED` 不再误判账号不可用。Skill 入口 SKILL.md 已收束为 ~80 行渐进披露结构，简介触发准确率由专用评测持续监测。

抖音能力仍必须按数据来源区分：

| 模式 | 能力 | 能否声明「全部作品」 |
|---|---|---|
| 任意公开账号、无需登录 | `collect.py --all` 在安全预算内滚动并被动观察公开列表响应；末页后停止滚动并排空到一次静默轮询 | **条件成立**。只有精确 HTTP 200、可选 API 状态为整数 0 的同账号可信列表明确出现 `has_more=false`，作品 ID/官方 URL 一致，且会话内全部目标账号列表候选形成账号/结构/分页事实一致的观测时，才写 `is_exhaustive=true`；HTTP/API 错误、歧义绑定、候选失败或分页冲突均非穷尽：已有作品为 `PARTIAL`，0 个有效作品为 `FAILED` |
| 用户授权 Cookie 会话 | `collect.py` 通过 `--douyin-cookie-file` 把用户合法会话注入隔离临时浏览器；默认不读取本机浏览器 profile、仅当前任务使用。显式 `--persist-cookie` 时，按平台把 Cookie 写入本地 `workspace/<platform>-cookies.json`（`0600`、`fsync`、原子替换、拒绝 symlink/UID 失配）供后续同平台任务加载 | **条件成立**。可继续匿名页因登录墙不可见的账号列表，但只有同样观察到可信末页时才声明穷尽；Cookie 过期、验证码、频控或绑定冲突仍可能得到 `PARTIAL/FAILED` |
| 已知公开作品 URL | `--enrich-details` 对列表中已有的真实作品 URL 补充缺失详情；不能据此发现新作品 | 不能；它只补已有作品字段 |
| 账号本人授权 | `collect_douyin_authorized.py --all` 先用同次 OAuth 的 access token + open_id 完成 userinfo 精确身份回证（仅接受官方 userinfo 在内存中返回的 `sec_uid` 作为 `account_id`），再使用官方 `/video/list/` 分页 | **条件成立**。只有官方响应 `has_more=false` 时才声明该授权账号的全部公开视频已遍历；当前仅完成离线契约测试（`tests/test_openapi_contract_repro.py` 六条断言），尚无真实凭据在线验收 |
| Web 索引证据 | Agent 核验公开精选页或精确主页索引后，由离线导入器生成可审计快照；显式日期窗口只保留发布时间可验证且在范围内的记录；可从同账号密封直连提交合并较新的公开资料 | 不能；固定为可能陈旧、非实时、非穷尽的 `PARTIAL`；日期未知的搜索索引不能用于「最近 N 天」排名 |

0.9.0 修正了若干边界误判：抖音浏览器回退 DOM 选择器被替换为多重 fallback 集合（profile / post list / detail 三层），与线上新版结构对齐；B 站 `-799`/明确频控文本继续映射 `RATE_LIMITED`，`-352/-412/-403/-400/-101` 继续 `ACCESS_RESTRICTED`；小红书 `login` 文本不再误判为登录墙，仅以可见页面文本为准；匿名页面 `userInfo.userId` 不再被当作被分析账号；授权资料失败时不再把 userinfo endpoint 写入 `profile_url`，OAuth 标识也不再进入公开账号字段。CSV 报告渲染前校验 `p25 ≤ median ≤ p75`、亚秒时长不截断、`task.json.phase_durations_ms` 之和等于 `duration_ms`、JSON 整数类型不再漂移。

核心运行时仍为 Python 标准库零额外依赖。浏览器路径可使用系统已有 Chrome/Chromium/Edge/Brave 或已安装的 Playwright Chromium/Headless Shell 缓存，但不新增 Python 包、不安装浏览器，也不接管本机浏览器 profile；B 站 WBI 签名通过包内 `sign_server.py` subprocess 端点提供，不引入第三方运行时。用户可在对话中粘贴授权 Cookie（统一 64 KiB 文件、128 条记录、4096 字符值上限、域名后缀匹配），默认仅在任务期受限临时文件中交接；只有显式 `--persist-cookie` 才以 `0600` 写入本地忽略的 `workspace/`，且不进入任务产物、报告与日志。测试需要 `pytest`，Web 索引取证需要 Agent 环境提供搜索/打开连接器，OpenAPI 全量路径需要账号本人提供同次 OAuth 返回的有效 access token 与 open_id。

## 数据字段可达性

| 数据 | 无登录公开主页/详情 | 用户授权 Cookie 会话 | Web 索引 | 账号本人授权 OpenAPI |
|---|---|---|---|---|
| 名称、简介、抖音号、认证、粉丝、作品数、获赞 | 页面公开时可采；不可见为 `null` | 用户登录后页面明确显示时可采 | 只保留来源明确显示的字段 | 官方 userinfo 在内存中回证同一 `open_id`，仅以公开 `sec_uid` 作为 `account_id`；产物只保留响应明确提供的公开字段；`profile_url` 不再写入 userinfo endpoint |
| 作品 ID 与规范 URL | 页面公开列表/详情可见时可采 | 登录会话列表/详情明确返回时可采 | 精选页可能有；搜索主页索引无真实 ID 时明确使用本地 `idx-*` 或 `xhs-card-*` 且 `post_url=null` | 官方 `video_id`；同 ID 的直接/数字 share URL 可写 `post_url`，非数字 opaque share 仅写 `source_url`，数字异 ID 拒绝 |
| 文案、发布时间、类型、时长、话题 | 列表或已知详情页公开时 best-effort；不猜测 | 同左，且只保留页面明确值 | 仅保留索引明确显示值 | 仅保留官方响应字段 |
| 播放、点赞、评论、收藏、分享 | 仅页面明确公开的指标；未显示为 `null` | 同左，不因登录态推算缺失值 | 仅保留索引明确显示值，不推算总互动 | 仅保留官方响应字段 |
| 评论文本与评论点赞 | `--comments` 开启且无需登录可见时，每篇最多 20 条 | 当前仍受页面接口与验证条件限制 | 不从搜索摘要拼接评论 | 当前授权采集命令不采评论 |
| 曝光、触达、完播、转化、粉丝画像、私信 | 不可采集 | 本项目不采集后台私有数据 | 不可采集 | 本项目不采集 |

## 最终需要登录或账号本人授权的能力

| 能力 | 所需身份 | 当前结论 |
|---|---|---|
| 稳定遍历抖音账号本人的公开视频列表并确认官方末页 | 账号本人完成 OAuth，提供同次返回的 `access_token + open_id` | 工程合同与离线测试完成（`tests/test_openapi_contract_repro.py` 六条断言覆盖 userinfo 逐字回证、token 隔离、`_SAFE_ERROR_CODES` 白名单、编排层身份二次核验、SKILL.md 文档完整性、frontmatter 结构守护）；仍需一组真实凭据在线验收 |
| 当前匿名页面已显示登录墙的第三方账号最近 30 条 | 用户在对话中提供其合法登录会话的 Cookie | 已实现 `--douyin-cookie-file` 隔离会话；Agent 只在任务期受限临时文件中交接，标记为 `user_authorized_session`，不冒充匿名采集，仍需实机验证 Cookie 有效性和平台可见性 |
| 当前匿名页面已显示登录墙的微博或小红书公开主页 | 用户在对话中提供其合法登录会话的对应域 Cookie | 已实现 `--weibo-cookie-file` 与 `--xiaohongshu-cookie-file`；Agent 只在任务期受限临时文件中交接，记录不写入工作区或报告，仍需实机验证 Cookie 有效性、页面可见性与字段准确率；小红书带 Cookie 的直接主页在登录墙或缺少嵌入状态时，最多使用一次隔离临时浏览器渲染同一 URL |
| 登录后才可见的评论列表或评论管理 | 账号本人授权及相应 OpenAPI 权限 | 当前只分析匿名公开评论；授权评论采集未实现，且不影响主内容分析 |
| 曝光、触达、完播、转化、粉丝画像等后台指标 | 账号本人后台登录/授权 | PRD 明确 Out of Scope，本 Skill 不采集；不是待补的匿名能力 |

人工 AC-03/AC-06 可以由真人打开页面填写真值，但登录后可见记录不能反向证明匿名采集能力。自动化流程不接管本机浏览器 profile，只使用用户显式提供的 Cookie 文件（统一 64 KiB 文件、128 条记录、4096 字符值上限、域名后缀匹配），并把访问方式写入覆盖账本。
